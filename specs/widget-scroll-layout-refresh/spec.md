# Widget Scroll, Layout, and Refresh

## 背景

- 创建日期：2026-09-02
- 功能标识：`widget-scroll-layout-refresh`
- 需求来源：小米设备实测发现编辑页保存后宿主未及时更新、4×6 桌面尺寸底部裁切，且用户希望 2×2 可选滚动展示超过三项任务。
- 第二轮真机反馈：延迟重试仍不能解决活跃 Glance 会话内的旧快照复用；添加任务后也会出现同样的刷新延迟，证明问题不只在 MIUI Launcher 接收 RemoteViews 的时机。

## 目标

- 编辑页保存并退出后，针对当前实例执行一次宿主恢复后的强制刷新。
- 将 4×6 预设改为顶部 16dp、底部 2dp，并将 2×2 默认圆角改为 22dp。
- 修复 4×6 静态三行布局的底部裁切，所有高度计算保留安全余量。
- 移除任务行的描边，只保留容器、状态色和指示条形成层级。
- 为 2×2 增加“允许滚动”实例配置；开启后使用 Glance 集合展示全部任务，关闭后最多三项。
- 让活跃 Glance composition 直接观察进程内渲染状态；数据库或配置变化时先发布最新快照/修订号，再请求宿主更新。
- 静态三行和滚动列表改为占用标题后的真实剩余高度，不再依据宿主上报高度手算列表 viewport。
- 2×2 内容区四边统一为 12dp；外层卡片背景使用 92% 不透明度，任务行和 2×1 保持原透明度。

## 非目标

- 不为 2×1 胶囊小组件增加任务列表或滚动能力。
- 不修改任务排序、筛选和 KMP 数据计算规则。
- 不在本轮改变 4×7 预设或用户已有的自定义 margin 值。

## 用户场景

1. 用户在小米桌面长按 2×2 小组件，修改圆角、边距、配色或滚动开关并保存，返回桌面后当前实例自动刷新。
2. 用户使用 4×6 桌面预设时，卡片保持顶部 16dp、底部 2dp，第三行不会被宿主裁切。
3. 用户开启滚动后，可在小组件内部上下滚动查看三项之后的任务；关闭后恢复固定三项布局。

## 验收标准

- 未配置的新 2×2 实例默认圆角为 22dp；4×6 预设解析为 top=16dp、bottom=2dp。
- 编辑保存使用同步持久化，提交完成后、配置 Activity 退出前先发布配置修订并刷新当前实例；针对 MIUI 再延迟重试一次，同时保留全量刷新兜底。
- 活跃 Glance 会话在刷新信号发布后必须立即读到新配置和新任务快照；不得继续依赖重新执行 `provideGlance`。
- 4×6、标准和 4×7 尺寸的静态布局测试均不超出可用高度。
- 2×2 的标题为固定高度，列表使用 Column/LazyColumn weight 消费剩余高度；静态模式的三行在该区域内等分，不产生累计 dp 舍入溢出。
- 2×2 内容区只使用一个四边通用 padding 常量，背景透明度在最终位图层统一应用，确保渐变和装饰的整体透明度一致。
- 自定义配色与跟随应用配色的任务行背景均不绘制 stroke。
- 2×2 编辑页展示滚动开关；配置可按实例保存、读取和删除，旧实例默认关闭滚动。
- 滚动模式渲染仓库返回的全部任务，静态模式最多渲染三项。

## 风险与约束

- Glance 1.1.1 的更新在活跃 session 内复用 composition，配置必须在重组阶段读取。
- Glance 1.1.1 明确说明 `update`/`updateAll` 不会重启仍在运行的 `provideGlance`，因此一次性捕获快照是本轮根因。
- Xiaomi Launcher 可能在配置 Activity 仍可见时忽略 RemoteViews 更新，因此刷新必须晚于 Activity 停止。
- Glance `LazyColumn` 是 RemoteViews 集合能力，必须使用稳定 item key，并避免把整个卡片点击手势覆盖到滚动容器。
- 无连接设备时只能完成静态、单测和构建验证；小米桌面真实刷新及滚动手势需安装验证。
