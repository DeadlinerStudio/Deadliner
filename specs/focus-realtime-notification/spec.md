# 专注计时实时通知

## 背景
专注前台通知缺少暂停/继续等操作，超级岛沿用普通文本模板，并每秒重新执行 Root 发布。

## 目标
超级岛采用模板 13（录音：highlightInfo + actions），原生 LiveUpdates 保留系统计时与标准通知操作。

## 非目标
不修改 KMP 计时引擎/数据库，不添加录音权限或功能，不更改任务/习惯静态实时通知。

## 用户场景
启动秒表或倒计时后，从通知暂停/继续、结束并保存，或结束并完成绑定任务；暂停冻结计时，完成/自然到时后关闭实时通知。

## 验收标准
- 业务名“专注计时实时通知”；超级岛录音模板显示白色计时、状态图标和文字，以及暂停/继续、结束两个圆形按钮；任务标题保留在原生通知和计时页。
- 运行态暂停，暂停态继续；结束保存本轮；结束并完成任务；由 KMP snapshot 的 can* 标志控制动作。
- 按钮 Intent 携带会话 uid、持久化 updatedAt 和能力 token，拒绝伪造、失效/跨会话/重复动作。
- 超级岛使用 timerInfo 自动计时，暂停固定数字；摘要大岛用同宽数字计时组件，小岛用时钟。避免每秒 Root 授权/notify。
- 原生使用标准 BigTextStyle + actions，支持 promotion；胶囊运行态 chronometer、暂停态状态文字，通知卡片提供操作；不用 RemoteViews。
- KMP 是会话和动作唯一权威；后台/重启重读持久化状态，倒计时自然结束沿用原 Alarm；没有当前计时立即移除通知。
- 日志接入标准 NotificationDiagnostics；Root 延迟回调重新读取当前会话，失效发布不复活卡片。

## 风险与约束
OEM 是否绘制录音模板及原生是否提升通知须真机确认。原生胶囊仅图标/计时，按钮在通知卡片。小模块拆分，核心文件小于 1000 有效行；整批后构建。不自动保存或丢弃用户未执行的会话。

## 实现结果

- KMP 新增只读 `focusTimerNotificationInfo`，返回会话版本及由共享引擎生成的 snapshot；过滤自然到时和绑定任务无效的卡片，不写入会话。
- 专注服务沿用恢复生命周期，运行态使用系统计时；时间推进不改变发布签名，只在会话/状态/动作/标题/模式变化时重新发布，Root 回调同步读取最新共享快照。
- 原生采用 BigTextStyle、chronometer 和三动作；API 36 模拟器确认被提升为 LiveUpdates 并能直接操作。超级岛模板 13 的最终视觉仍需小米真机验证。

## 真机反馈修订

- 展开态移除辅助任务标题，释放状态文字空间；只保留暂停/继续和结束，原生通知仍支持结束并完成任务。
- 录音横向模板 type=0 走图标分支，不读取 actionBgColor。使用系统内置 action_pause_record / action_restart_record / action_record_end，获取系统录音样式的圆形背景、图标和尺寸；动作仍绑定原来的版本校验 URI。
- 大计时浅色/深色均使用白色，状态文字和功能时钟沿用运行蓝色、暂停灰色；运行态仍只传 timerInfo。

- 三个圆形操作显式设置浅色/深色容器背景和前景，图标在 88px 资源画布内居中缩小到 44px，避免图标铺满按钮。
- 运行态大岛数字只传 timerInfo，不同时传静态 digit；暂停态仅传 digit，避免静态数字抢占计时组件。
- 必须核对实际协议是否支持摘要计时；真机效果和暂停冻结继续复测。

## 专注结束鼓励通知（2026-10-09）

- 手动结束、结束并完成任务、倒计时自然结束生成 KMP 平台无关 FOCUS_RESULT 元数据，保留三分钟；丢弃、任务失效导致终止不生成新结果。
- 元数据包含对应任务、专注记录、时长、结果期限及 OPEN_TASK 操作，界面使用绿色 TopDownloads、专注完成和“做得好”；收起态静态提示、展开态显示本轮时长。
- 原生 LiveUpdates 和超级岛的快捷操作均打开本次专注任务详情；不再次操作计时或任务状态。
- 监听已提交专注记录和当前计时变更，支持从计时页、通知按钮、闹钟结束及进程恢复；新计时期间隐藏旧结果，过期、删除记录或任务时移除，修改时长不延长结果期限。
- 同一任务的完成结果被专注结果替代，避免重复鼓励卡片；未完成任务的临近/到期提醒继续保留。
- 其他平台共用 KMP 元数据。iOS 当前为 ActivityKit 示例模板，鸿蒙无实况窗适配，用户已确认本轮完成 Android 与共享层，其他平台原生实况适配留待接入。
