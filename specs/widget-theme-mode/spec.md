# 小组件强制深浅色模式

## 背景

小组件目前固定读取系统深浅色，不能按壁纸独立设置。

## 目标

每个实例提供跟随应用、强制浅色、强制深色；作用于背景、文字、状态颜色及滚动任务行。应用目前跟随系统深浅色，默认保留此行为。

## 非目标

不改变应用整体主题、透明度、点击和滚动协议。

## 用户场景

用户在小组件编辑页选择强制深色，预览及配色样本切换至深色，保存后桌面实例和滚动列表一致使用深色；再次编辑恢复选项。

## 验收标准

- 两种尺寸均提供三个选项，逐实例持久化；缺失或未知值回退跟随应用，删除实例清理配置。
- 强制模式在相反系统模式下仍使用指定深浅色，默认随系统切换。
- 编辑预览与配色样本使用指定模式，文字与背景匹配。
- 两个 Glance 布局与滚动集合共用解析策略，保留背景透明度。

## 风险与约束

不能只调整背景而遗漏文字或服务列表；预览必须使用小组件调色板，不能用编辑页主题的文字颜色替代。无破坏性变更，完成实现后统一测试与构建。

## 后台跟随系统刷新修复

- 进程存活时通过 Application 注册的 ComponentCallbacks 接收配置变化，深浅色改变触发强制刷新；不再依赖 Manifest 的 CONFIGURATION_CHANGED。
- 普通任务更新与主题更新合并时保留强制刷新，避免相同快照去重吞掉外观变化。
- 同步失效活跃 Glance 配色并通知滚动列表；强制深/浅色实例仍按自己的配置解析。
- 此回调针对存活进程；不承诺强制停止或进程被杀后能由配置变化唤醒应用。
