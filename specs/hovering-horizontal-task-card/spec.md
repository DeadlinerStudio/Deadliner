# 带悬停的横向滑动任务卡片

## 背景

Android 任务卡片当前使用 `SwipeToDismissBox`，每侧只承载一个动作，松手后直接回弹；iOS 使用系统 `swipeActions`，鸿蒙已按同一语义实现为可停留的双侧操作区。三端的手势反馈和动作入口不一致。

## 目标

- Android 任务卡片横向短滑后可悬停并露出两个操作按钮。
- 右滑依次提供主要状态动作与次要状态动作；左滑提供编辑与删除。
- 完整滑动执行靠外侧的主要动作：右滑执行完成/恢复，左滑执行删除。
- 同一列表同一时间只允许一张任务卡片保持展开。
- 选择模式禁用横向滑动，并保持原有点击、长按选择行为。

## 非目标

- 不修改 iOS 或 HarmonyOS 代码。
- 不改变任务状态机、持久化模型或列表排序。
- 不改造习惯卡片、归档页卡片及搜索结果卡片。

## 用户场景

用户轻扫任务卡片后，可以停留并点击具体动作；继续大幅滑动时，可以快速完成/恢复或删除任务。展开另一张卡片时，上一张自动收起。

## 验收标准

- 从关闭态滑过触发距离后，卡片稳定停在左右 `112dp` 操作位。
- 从展开态向关闭方向拖动超过 `32dp` 后收起；小幅拖动则回到展开位。
- 滑动超过卡片宽度 `62%` 时，右侧执行主要状态动作，左侧执行删除。
- 操作按钮保持圆形且仅展示图标，文字 hint 位于按钮正下方；超出悬停位后操作槽与间距继续增长。
- 按钮前景色根据背景亮度自动选择黑或白，深色模式下仍保持可读。
- 启用“多彩任务指示标—中和”时，完成、放弃、编辑和归档语义色使用 `harmonizeWithPrimary`，删除使用当前 `colorScheme.error`；归档始终使用灰色语义。
- 点击展开的卡片先收起，不打开详情；点击按钮执行且收起。
- 选择模式下不响应滑动，长按和选择覆盖层行为保持不变。

## 风险与约束

- `Components.kt` 已接近 1000 行，需要把滑动规则与展示组件拆到独立文件。
- 当前工作区有用户正在进行的小组件改动，本功能不得覆盖或提交这些改动。
- 本次属于 UI 交互替换，不涉及数据层 breaking change；最终集中执行单元测试与 Android 编译。
